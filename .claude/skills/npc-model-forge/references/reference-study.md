# 잘 만든 3D NPC 모델은 기하학적으로 무엇을 하는가 (2026-08-08 실측)

감으로 흉내내면 헛다리를 짚는다. 스킨 때 그렇게 네 번 틀렸다(`female_face` 얼굴 파괴,
앞머리 3회, 세로 주름=줄무늬 바지). 그래서 **실제 파일을 열어 숫자로 재고**, 우리 것과
같은 잣대로 비교해 격차가 있는 항목만 처방한다.

표본: moonlit.kr의 ModelEngine 블루프린트 **사람형 10종**(클라이언트가 받아둔 서버
리소스팩에서 추출). 측정 도구는 `scripts/megstudy.py`(컴파일된 vanilla JSON) ·
`scripts/bbstudy.py`(우리 .bbmodel 소스).

## 1. 숫자 — 우리 NPC는 '뼈로 자른 바닐라 플레이어'였다

| 모델 | 본 | 큐브 | 큐브/본 | **회전%** | **판%** | 크기변동 |
|---|---|---|---|---|---|---|
| moonlit 평균(10종) | 19 | 43 | 2.17 | **16.0** | **61.5** | 1.73 |
| └ catherine (최고급) | 30 | 90 | 3.00 | **30.0** | **84.4** | 2.27 |
| └ luka | 15 | 50 | 3.33 | 54.0 | 82.0 | 3.32 |
| **steve (우리 NPC 베이스)** | 18 | **26** | **1.44** | **0.0** | **7.7** | **0.90** |
| demon_knight (우리 보유) | 30 | 323 | 10.77 | 75.9 | 70.6 | 10.02 |
| blue_wizard (우리 보유) | 34 | 207 | 6.09 | 73.4 | 96.6 | 10.99 |

**격차의 정체**: 우리 NPC가 쓰는 `steve`는 회전 0% · 판 7.7% · 크기변동 0.90이다.
= 바닐라 플레이어 박스를 본으로 쪼개기만 한 것. **조형이 하나도 없다.**

★반대로 `demon_knight`·`blue_wizard`는 moonlit보다 오히려 복잡하다(회전 75%, 크기변동 10).
  즉 **우리 서버는 이미 그 급의 모델을 돌리고 있다** — NPC가 그걸 안 쓰고 있을 뿐이다.

★회전각은 **22.5° / 45°만** 쓰인다. 바닐라 JSON 제약(요소당 한 축, 정해진 각)이라
  ModelEngine/BetterModel이 그렇게 굽는다. 소스에서 자유각을 줘도 결국 이 격자에 맞춰진다.

## 2. 부위별 레시피 (catherine 해부)

숫자보다 이쪽이 실전에 직결된다. 크기는 `[너비, 높이, 깊이]` px.

### 몸통 — **45° 판으로 모서리를 깎는다** ★1순위 기법
```
torso: 큐브 11 (평면 8 · 회전 6)
  실체  7×3×4 · 6×6×3        ← 몸통 본체
  평면  3×3×0  rot ±45°/z    ← 어깨 모서리를 비스듬히 덮는다
  평면  0×3×3.95 rot ±45°/z  ← 옆구리 모서리
```
각진 박스에 **45° 기울인 얇은 판**을 모서리마다 붙이면 면이 깎여 유기적으로 보인다.
바닐라가 못 하는 걸 이걸로 해결한다. 회전%가 높은 모델이 잘 만들어 보이는 진짜 이유다.

### 머리카락 — **사슬 + 테이퍼**
```
hair_left     4×4×3   ← 뿌리
hair_mid_left 3×5×2   ← 중간 (좁아짐)
hair_end_left 2×4×2   ← 끝 (더 좁아짐)
```
본 3단 사슬, 각 1큐브, **폭이 4→3→2로 줄어든다**. 전부 실체(평면 아님).
사슬이라 애니메이션에서 순차적으로 흔들린다.

### 모자 — **챙은 머리보다 2배 넓게, 두께 0**
```
crown 7×2×7        (실체)
brim  17×0.02×17   (평면) ← 머리 8px 대비 2배 이상
```
챙을 머리 폭에 맞추면 안 보인다. **과장이 정답.**

### 천(케이프·앞치마) — 평면 한 장
```
cape  18×9×0   ← 몸통 8px 대비 2배 폭
apron 5×6×0
```

### 천(주름진 것) — **평면을 조합한 껍데기**
```
drape_left: 큐브 7, 전부 한 축이 0
  3×7×0 · 0×7×5 · 3×3×0 · 0×3×3.5 · 3×0×5 · 3×3×0 · 3×7×0
```
평면 6~7장을 상자 껍데기처럼 세워 **속이 빈 부피**를 만든다. 실체 박스보다 가볍고
가장자리가 얇아 천처럼 보인다.

### 손 — **작은 실체를 틀어 붙인다** (평면 0)
```
palm_left: 큐브 5, 평면 0, 회전 4
  1×3×2.9 rot -22.5°/z · 2×1×0.85 rot 45°/z · 1×1×1.95 · 1×2×2 rot 22.5°/z …
```
부피가 필요한 곳은 평면을 쓰지 않는다.

### 얼굴 표정 — **스킨 텍스처 위에 작은 큐브를 덧댄다**
```
blink        2.05×2.05×2 실체 ×2  ← 눈 위에 살짝 큰 눈꺼풀. 내려오면 감긴 눈
eyebrow_left 2.75×0.75×0 평면     ← 얼굴 앞에 띄워 붙임
```
64×64 스킨의 눈은 그대로 두고, **그 위에 덮는 큐브**로 표정을 만든다.

## 3. 규칙으로 압축

1. **모서리는 45° 판으로 깎는다.** 회전 0%면 무조건 레고로 보인다. 목표 **회전 15~30%**.
2. **부피와 천을 구분한다.** 손·머리·머리카락·본체 = 실체. 케이프·앞치마·챙·눈썹 = 평면.
   목표 **판 55~85%**(천이 많은 캐릭터일수록 높다).
3. **소품·장식은 과장한다.** 챙 17 vs 머리 8, 케이프 18 vs 몸통 8. 실물 비례로 하면 안 보인다.
4. **흔들리는 것은 사슬 + 테이퍼.** 본 3단, 폭 4→3→2.
5. **큐브 크기를 섞는다.** 크기변동 1.7 이상. 전부 같은 크기면 조형이 아니라 분해다.
6. **본당 큐브 2개 이상.** 1본 1큐브는 '뼈로 자른 바닐라'다(우리 steve가 1.44).
7. **얼굴은 스킨에 맡기고 큐브는 덧대기만.** 8×8 얼굴을 큐브로 다시 만들지 않는다.

## 4. ★평면 사용에 대한 경고 (오너 규칙과의 관계)

오너 규칙에 **"X자 크로스 금지 — 교차평면 2장으로 3D인 척 금지"**가 있다.
위 레시피의 평면은 그것과 **다른 것**이므로 혼동하지 말 것:

- ❌ 금지된 것: 평면 2장을 X자로 교차시켜 **입체가 아닌 걸 입체인 척** (버섯·풀 스프라이트)
- ✅ 여기서 쓰는 것: **실제로 납작한 것**을 납작하게 (케이프·앞치마·모자챙·눈썹),
  그리고 **실체 박스의 모서리를 깎는 덮개**로서의 45° 판

즉 "평면으로 부피를 위조하지 마라"는 규칙은 유지된다. 부피가 필요한 손·머리는
catherine도 평면을 0% 쓴다 — 레퍼런스가 같은 원칙을 지키고 있다.

## 5. 아직 검증 못 한 것

- **오프라인 렌더러가 없다.** 이 문서의 규칙대로 만들어도, 보지 않고 판단하면
  스킨 때와 같은 실패를 반복한다(4회 전례). 렌더러가 선행 작업이지 선택이 아니다.
- 본 계층·피벗은 리소스팩의 컴파일된 JSON에 안 남는다(이름으로만 추정). 소스 .bbmodel을
  구할 수 없으므로 계층은 우리가 설계해야 한다.
- 머리카락·케이프의 물리(흔들림)가 BetterModel에서 어디까지 되는지 미확인.
