### 체인 무결성

- 완성 요리 재료 타입 `dish`를 추가해 아이템 lore의 `dish:<id>`를 정확히 검사한다.
- 일반 요리와 완벽 요리를 같은 id로 인정하므로, 완벽 요리를 중간재로 써도 정상 소비된다.
- `dish` 참조 34개, 참조 대상 누락 0개, 순환 0개.
- 튜토리얼 필수인 `따뜻한 빵`은 원재료 레시피로 유지해 신규 유저 진행을 막지 않는다.

### 버프가치 관찰

현재 스냅샷 stat-value 기준 단일 요리 1개분의 금전 환산은 T1 약 75~148원, T2 약 40~225원, T3 약 384~504원, T4 약 96~1,157원이다. T2·T4 편차가 3배를 넘지만, 낮은 값의 `도주감소`와 높은 값의 `난이도`는 금전 수입 외 효용이므로 즉시 수치를 평준화하지 않았다. 🟡 다음 telemetry에서 실제 미니게임 성공률·도주율과 함께 재평가한다.

## K. 획득경로 / 기회비용 / 지배구간

- 🟢 완성 요리는 실제 아이템 marker를 소비하므로, 이름이 같은 바닐라 음식이나 재료 lore만으로 우회할 수 없다.
- 🟢 중간재 생산은 `CookingGui`의 기존 재료 체크·차감·대기열 경로를 그대로 사용한다.
- 🟡 `왕실케이크`처럼 여러 단계가 겹치는 최종 레시피는 요리 숙련 XP를 빠르게 제공할 수 있다. 실제 제작 빈도를 수집한 뒤 해금 curve를 조정할지 결정한다.

## 드리프트 (코드 vs balance.md)

- ⚪ `balance.md`의 일부 요리·난이도·과거 시급 서술은 현재 Java/JSON 스냅샷과 역사적으로 어긋난다. 이번 변경에서는 권위 소스인 `DishSpecs.java`와 runtime `recipes.json` 생성 경로를 우선했다.
- ⚪ 현재 스냅샷의 `recipes.json`은 서버 재시작 전이라 새 `dish` 재료가 아직 반영되지 않았다. 재시작 후 `RecipeLoader.ensureCookingRecipes()`가 Java 단일 소스에서 자동 동기화한다.
