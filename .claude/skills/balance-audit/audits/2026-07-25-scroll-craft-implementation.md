# 강화 주문서 대장간 조합 신설 (2026-07-25, 실제 구현)

## 배경
낚시 감사 조치권고 논의 중 발견: 강화 주문서(강화확률상승/하락확률감소/하락방지)는 **캐시상점
전용**이었다(`CashShopData.java`, "캐시"=`d.getCash()`, `/캐시지급`은 OP전용 → 게임 내 획득경로
전혀 없음 확인). 사용자 지시: "주문서를 그냥도 만들 수 있게 하자, 밸런스 맞는 적절한 재료로
대장간에서."

## 설계 — 재료비 산정 근거
강화 기대비용 선형방정식(이미 이번 세션에서 확립)으로 각 주문서가 "얼마를 아껴주는지" 먼저 계산:
- Lv10 단발 확률상승30%: 성공률35%→45.5%, 절감 ≈164,835원
- Lv13: 성공률23%→29.9%, 절감 ≈1,254,181원
- Lv14: 성공률20%→26.0%, 절감 ≈2,423,077원
- Lv15: 성공률17%→22.1%, 절감 ≈4,751,131원

실사용은 레벨에 따라 편차가 크다(고레벨일수록 훨씬 이득). **재료비를 이 절감액의 극히 일부
(1~2%대)로 앵커링** — "확실히 이득이지만 공짜는 아닌" 지점. 기존 캐시가격 비율(디자이너가 이미
정한 상대강도: 하락방지 1:2.5:5:8, 강화확률상승 1:2:3, 하락확률감소 1:2:3.33)은 그대로 유지하고
절대값만 [cross-economy-values.md](../references/cross-economy-values.md) 골드가치로 앵커링.

## 구현 상세
- `EnhanceManager`는 아이템 **lore 텍스트 파싱**으로만 주문서를 식별(`hasTag`/`scrollBoostPercent`/
  `downRedPercent`/`shieldTier` — PDC 아님). 조합대가 만든 `Material.PAPER`+동일 lore 포맷
  (`"scroll:강화확률상승:30"` 등)이면 캐시상점 산출물과 **완전히 동일하게 작동** — 강화 GUI가
  둘을 구분 못 함(의도대로).
- `RecipeLoader.load()`가 `!file.exists()`일 때만 하드코딩 시드 사용 → 기존 recipes.json에 직접
  추가한 10개 레시피는 서버 재시작해도 안 덮어써짐(안전 확인).
- `category="재료"` → 기존 `CraftingGui`의 5탭(낚싯대/부품/재료/드릴/통발) 중 "재료" 탭에 자동 노출,
  신규 UI 코드 불필요.
- 재료 typeOrMatId/mcItem 전부 기존 라이브 레시피에서 실사용 확인된 값 그대로 재사용(흑정석=
  black_stained_glass, 자수정=amethyst_shard, 압축흑정석=blackstone, 강화다이아몬드=diamond,
  강화금괴=gold_ingot, 강화에메랄드=emerald, 작물_X=CropSpecs 매칭, 채집_라벤더선반버섯/채집_
  핏빛수정초=forage-types.json 실사용 항목).
