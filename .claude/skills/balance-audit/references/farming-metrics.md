# 농사 감사 지표 · 정상 범위 · 계산 공식

## 처리량 지표 (직접 판매가 없어 원/h 대신 "개/h"가 1차 잣대)
```
개/h = 산출수량 × 3600 / growSec
```
크로스이코노미 원칙(SKILL.md 공통원칙4)과 동일한 이유로 여기도 **가격≠가치**: 작물은 광석처럼
직접 판매경로가 전혀 없다(전량 `mat:작물_X` 마커, 요리 인풋 전용). 요리 판매가로 역산하려 해도
대부분의 요리 레시피가 작물+광물(강화X)+낚시재료를 함께 섞어 쓰므로, **작물만의 순수 원화가치를
깔끔하게 분리할 수 없다**(연립방정식이 필요 — 광질도 같은 문제라 두 경제 다 "직접가격 없음"으로
수렴). 1차 지표는 **개/h**(작물 슬롯 하나의 시간당 산출). ★2026-07-25 해결: 연립방정식 대신
**슬롯임대료 모델**(농사는 수동경제라 growSec 자체가 비용이 아니라 "슬롯 점유 기회비용"이 진짜
비용)로 순수 골드가치 산출 완료 — [cross-economy-values.md](cross-economy-values.md) §3 참조.

## 정상 범위 / 경보선
- 밀~토마토(20분~1시간) 개/h 스펙트럼 2.0~9.0, 4.5배 이내 — 완만한 곡선, 정상.
- 🟡 **수박(24시간) 이상치**: 개/h가 다음으로 느린 토마토의 **1/12**, 밀의 **1/54**. 다른 작물과
  자릿수가 다른 "하드 커밋" 설계 자체는 의도적일 수 있으나(balance.md에 명문화된 근거 없음 —
  드리프트 아님, 그냥 문서가 아직 없음), **다이닝 레시피가 수박을 대량 요구하면(예:
  스터프드캔털루프 T2 요리가 특수수박8 요구 = 최소 2회 수확 = 48시간+) 요리 하나 만드는데
  며칠씩 걸리는 부담이 생긴다** — 요리쪽 감사(F절, 이미 완료)와 교차 확인 권고.
- 🔴 트리거: 만약 수박 필요 요리의 판매가/버프가치가 다른 재료 대비 시간투자를 정당화 못 하면
  치명(재료 낭비 콘텐츠). 다음 감사에서 수박-소비 요리 전수 대조 권장.

Lv1→5 개인 810,000원(+28칸)/길드 4,050,000원(정확히 ×5, CLAUDE.md 컨벤션 준수 — 🟢).
- 칸당 비용 우상향(30k→80k→200k→500k, 개인 기준) — 표준적인 체감형 업그레이드 곡선. 정상.

## 판정 등급
🔴 치명 · 🟡 주의(수박 이상치, 요리 대조 필요) · 🟢 정상 · ⚪ 드리프트(해당 없음 — 문서 자체가 없었음)

## 크로스이코노미 연결
- 요리(F절, 이미 감사됨)가 작물을 원료로 씀 — 요리 판매가/버프가치 재계산 시 작물 개/h와 대조.
- 수박 관련 요리: `스터프드캔털루프`(특수수박8) 등 확인 필요(recipes.json 재조회).
