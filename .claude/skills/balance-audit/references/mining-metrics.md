# 광질(mining) 감사 지표 · 정상 범위 · 계산 공식

낚시와 근본적으로 다른 구조: **낚시=수입+소모 양방향 경제, 광질=거의 순수 소모(money) +
재료생산(크래프팅 인풋)**. 흑정석/자수정/섬광산 원석 전부 `SellCommand`(물고기 전용) 판매 경로가
없다 — 확인 완료(economy/SellCommand.java, SellGuiListener.java grep 무결과). 돈은 드릴
구매(3,000)+레시피해금(10,000+30,000)+모자(2,000)로만 나가고 들어오지 않는다.

## 두 시스템의 처리량 성격이 완전히 다름 — 반드시 구분해서 판단

### 드릴 채굴 (`mine`월드/레드_로드)
- **자연 제약 있음**: `needed = breakTicks/tierSpeed` 파괴시간 + `regenSeconds`(180~480s) 재생 대기.
- 채굴존에 광맥이 몇 개 있는지(레이아웃)에 따라 실제 시간당 처리량이 갈림 — **이 숫자는 서버
  빌드 데이터라 코드에 없음**. 감사 시 "광맥 개수 대비 유저 수" 현장 확인 필요(추정 금지).
- 티어체감: T1→T3 배속 3.5배. 티어3 획득 총비용 = 3,000+10,000+30,000=43,000원 + 압축흑정석24개
  (T2레시피8+T3레시피16) — 압축흑정석 자체가 흑정석9개 조합이라 순환참조(첫 압축흑정석은 T1으로
  캐야 함).

### 섬 광산 생성기 (island_world/guild_world)  ★2026-07-25 운영자 확인으로 판정 정정
- **코드만 보면** `IslandMineListener.onBreak`이 `BlockBreakEvent`를 가로채 드롭만 바꾸고 바닐라
  파괴속도는 그대로 통과시킨다(즉시재생, 쿨타임 없음) — 이것만 보고 "처리량 무제한"이라 오판했었다.
- **실제로는 3중 안전장치가 이미 있음**(운영자 확인):
  1. 호퍼(자동수집) 개수가 섬 레벨별 캡(`HOPPER_LIMIT={0,8,16,32,64,128}`) — AFK/매크로 대량화 원천봉쇄.
  2. 효율4+ 곡괭이·인챈트북은 상점 미판매 + **인챈트 테이블에서도 효율5 자체가 안 나옴**(서버 실측).
  3. 효율4+헤이스트2 조합으로도 "우다다닥" 채굴 안 됨(서버 실측).
- **교훈**: 코드에 명시적 쿨타임/캡이 없다고 "무제한"이라 단정하지 말 것. 인접 시스템(호퍼캡·
  인챈트상한)이 암묵적으로 상한을 만들 수 있다 — **판정 전에 운영자에게 실측/체감을 반드시 확인**.
- 최종 판정: 🟢. 조치 불필요.

## 정상 범위 (baseline)
- 드릴 T1→T2→T3 배속 1.0→2.0→3.5. 단조증가·과도한 스파이크 없음 → 🟢.
- 광석별 breakTicks 30~90(자수정계는 40~90) — 등급 상승할수록 파괴시간↑+재생시간↑(경제적 마찰
  증가) → 설계 의도상 합리적, 다만 **섬광산과 달리 이 마찰 자체가 곧 안전장치**이므로 손대지 말 것.
- 섬광산 가중치(돌35%~다이아/에메랄드5%)는 그 자체로는 정상적인 희귀도 곡선 — 문제는 확률이
  아니라 **처리량 무제한**(위 🔴 항목).
