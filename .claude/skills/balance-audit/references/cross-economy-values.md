# 전 경제 통합 골드가치표 (2026-07-25)

사용자 지시: "모든 시스템의 가치를 분석해서 밸런스를 맞춰라, 정확한 가치들을 골드로 정하면 됨."
낚시·광질·농사·채집 전체 원재료에 **하나의 공통 골드가치**를 매긴다. 산출 스크립트:
`scripts/cross_economy_values.py` (재계산 가능, 낚시 시급이 바뀌면 전체 자동 갱신).

## 공통 앵커
**낚시 무버프 시급 32,489원/h = 9.0247원/초** (stat_value.py 기본 시나리오, 150캐스트/h 품질50).
모든 "능동" 경제(플레이어가 그 시간 동안 다른 걸 못 하는 경제)는 이 앵커로 환산 — 낚시보다 시급이
낮으면 "이걸 할 이유가 없다"(다들 낚시하지 왜), 높으면 "이게 낚시보다 이득"이 되므로 이 앵커가
전 경제의 자연스러운 균형점이다.

## ★경제마다 "시간"의 의미가 다르다 — 4가지 원가모델
| 경제 | 시간 성격 | 원가모델 |
|---|---|---|
| 낚시 | 완전 능동 | 캐스트당 시간 × 앵커 (이미 정립) |
| 드릴채굴 | 완전 능동 | breakTicks(T1기준) × 앵커 |
| 섬광산 | 반능동(도구+호퍼캡으로 안전제약 확인됨) | 블록당 추정시간 × 앵커 (★가정: 1.5초/블록, 광클 불가 확인) |
| 농사 | **수동**(성장중 다른 활동 가능) | growSec는 비용 아님 — **플롯슬롯 임대료** 모델 |
| 채집 | 능동(단, 노드밀도 미지수) | 8스윙 행동시간 × 앵커 (**floor값**, 밀도 낮으면 실제는 이보다 낮음) |

## 검증 — 요리 버프가치와 대조 (판매가 아닌 버프가치가 진짜 산출물 가치)
★함정: 요리 **판매가**(예: 파스타 240원)로 검증하면 재료비(토마토2×126.6+밀2×28.1≈309원)보다
낮아 보여 "손해"처럼 보인다. 그러나 **요리의 진짜 가치는 버프가치**다(stat_value.py 기반, 이미
E/F절에서 산출: 파스타=1,236원). 버프가치 기준으로 재검증하면 1,236원 ≫ 재료비 309원+α — 건전한
마진. **판매가는 처분용 소액이지 산출물의 진짜 가치가 아니다** — 향후 감사에서 요리/장비 등
"만들어 쓰는" 산출물은 반드시 버프/스탯가치로 검증하고 판매가로 검증하지 말 것.

## 잔여 불확실성 (명시적 가정 — 데이터로 교체 가능)
1. **드릴 채굴존/채집 노드 밀도**: 서버 빌드 데이터라 코드에 없음. 위 채집값은 "행동당 floor"이며
   실제 시간당 개수(밀도 낮으면 대기시간 추가)는 이보다 낮을 수 있음.
2. **섬광산 블록당 1.5초**: 운영자가 "광클 불가"를 확인해줬으나 정확한 초 단위는 가정치. 서버에서
   실측(스톱워치) 시 교체 권장.
3. **농사 슬롯 생애 100시간**: 순수 가정. 실제 플레이어 평균 슬롯 점유기간 데이터로 교체 가능.
4. 위 셋 다 **결론에 영향 없는 정도의 오차** — 상대적 순위(어느 재료가 비싼지)는 가정치 조정에도
   안정적(민감도 낮음), 단 절대값은 참고용으로 취급할 것.
