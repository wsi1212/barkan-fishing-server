## A. 레벨링 / 성장 곡선 대비

현재 런타임은 더 심하다. Lv.20에서 전문 일일 한 묶음이 다음 필요 EXP의 2.68배라, 일일 올클리어 한 번으로 두 레벨 이상을 건너뛸 수 있다.

## C. 구현 경로 영향

- `QuestManager.acceptDaily()`는 선택한 난이도의 풀 전체를 플레이어에게 배정한다. 따라서 표의 각 티어 합계는 “최대 한 퀘스트”가 아니라 실제 하루 올클리어 상한이다.
- `QuestManager.checkWeekly()`는 주간 목록에서 필요 레벨을 만족하는 항목을 전부 자동 배정한다. 현재 런타임은 Lv.1에서 6종/1,321 EXP, Lv.5에서 14종/3,052 EXP, Lv.10에서 22종/5,112 EXP, Lv.15에서 33종/8,152 EXP, Lv.20부터 36종/8,900 EXP가 된다.
- `giveReward()`는 `보상경험치`를 그대로 `FishingLevelManager.addExp()`에 넣는다. 보상 XP에 별도 일일·주간 캡이나 감쇠가 없다.

## 조치 권고

1. **[🔴] 현재 런타임 카탈로그를 교정** — 개발 소스의 활동형 16일/16주 구조를 배포하거나, 최소한 런타임 주간 36종의 `보상경험치`를 즉시 0으로 맞춘다. 현재 주간 8,900 EXP는 설계 문서와 정면으로 충돌한다.
2. **[🔴] 개발 소스 일일 보상은 기준선으로 복귀** — 쉬움 210 / 보통 375 / 어려움 750 / 전문 1,500 EXP. 현재 소스의 보통·어려움·전문은 일일 풀 전체가 레벨 게이트를 과도하게 밀어낸다.
3. **[🟡] 활동 다양화는 보상 XP가 아니라 돈·재료·제작 루프로 보상** — 주간 XP 0 정책은 유지하고, 일일 전문의 제출·특성처럼 시간이 짧거나 이미 가진 자원으로 즉시 처리되는 목표는 특히 XP를 낮게 두는 편이 안전하다.
4. **[🟡] 배포 후 검증** — 로그에 `Loaded 268 quests`가 찍히는지, 런타임 JSON의 일일/주간 카운트와 `보상경험치` 합계를 다시 확인해야 한다. 단순히 소스 JSON만 고치고 서버 런타임 파일을 남기면 이번 드리프트가 반복된다.
