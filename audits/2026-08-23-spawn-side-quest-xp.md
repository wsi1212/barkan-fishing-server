## 설계/코드 불일치

- `story.md`는 사이드 퀘스트를 “완료 후 재수락 가능(반복형)”으로 설명하고 보상을 메인의 60~80%로 잡고 있다.
- 실제 `QuestManager.accept()`는 `일일`, `주간`, `반복`만 완료 후 재수락한다. 현재 52개는 모두 `카테고리: 사이드`이므로 문서 설계와 실제 행동이 다르다.
- 이 불일치는 XP 튜닝보다 먼저 결정해야 한다. 1회성이라면 지금처럼 5~25 EXP가 대부분인 보상은 체감이 거의 없고, 반복형으로 바꿀 것이라면 같은 값을 그대로 올리는 순간 장기 수입원이 된다.

## 권장 조치

1. **1회성/반복형 정책을 먼저 확정**한다. 이번 범위에서는 현재 코드 동작인 1회성 기준으로 판단했다.
2. 라이브 52개를 기준으로 최종 보상표를 다시 만든다. 개발 소스는 목표·선행조건이 다르므로 EXP만 일괄 복사하지 않는다.
3. 현재 곡선의 `필요레벨`별 필요 EXP를 기준으로, 단일 목표·짧은 심부름 / 복합 목표 / 장기 캡스톤을 서로 다른 보상 밴드로 나눈다. 첫 검토안은 일반 퀘스트를 대략 **필요량의 30~60%**, 복합·장기 퀘스트를 **60~100%** 범위에서 잡고, 전체 퀘스트가 한 게이트에 몰려 50% 설계 의도를 초과하지 않는지 연쇄 합계로 검증하는 것이 안전하다.
4. 마인팜과 도감 캡스톤은 성장 시간·칭호·현금/아이템 보상이 함께 있으므로 일반 낚시 심부름과 같은 단일 비율로 맞추지 않는다.
5. 보상표 확정 후 라이브 JSON과 Git 미러를 함께 수정하고 JSON 검증 및 `/데이터리로드`로 적용한다. 이번 감사에서는 이 변경을 수행하지 않았다.
