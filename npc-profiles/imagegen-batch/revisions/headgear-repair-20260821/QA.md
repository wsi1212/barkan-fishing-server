# 요한(길드접수원, Citizens 162) 초상 «널빤지 헤드기어» 제거 — 2026-08-21

## 증상
머리 위에 정육면체 하나 + 좌우로 뻗은 빗살 널빤지 두 장이 십자로 얹혀 있었다.
모자도 머리카락도 아니고, `base` · `progress` · `complete` 3상태 전부 같은 아티팩트를 갖고 있었다.

## 원인 — 생성 단계 (프레이밍/합성 무관)
- 아티팩트는 **배포 전 원본(raw)에 이미 있다**: `style-test/batch15-skin-confirmed/raw/162_길드접수원.png`
  (크로마키 초록 배경 상태의 생성 직출력)에서 확인. 널빤지 이빨 사이에 초록 스필까지 남아 있다.
  → 크로마 제거·정규화·프레이밍은 범인이 아니다.
- 형태가 무엇을 베낀 것인지도 특정된다. `queue.json[144]` 의 프롬프트는 참조 이미지로
  ① identity 보드 ② **64×64 스킨 텍스처 원본**을 넣고 "headwear 를 보존하라"고 지시한다.
  hagen 스킨에는 모자가 **없고**, 그 아틀라스는 머리 6면이 위쪽에 펼쳐진 평면 배치다.
  생성 모델은 그 **펼친 아틀라스를 «머리에 쓴 입체물»로 읽어** 정육면체(머리 상자) +
  머리카락 outer 레이어의 톱니 스트립(빗살 널빤지)을 머리 위에 그렸다.
  `revisions/regeneration-20260812/QA.md` 의 「모자 없는 스킨에는 새 모자 추가 금지」와 같은 계열의 사고다.
- `progress`/`complete` 는 base 의 framed 이미지를 입력으로 재생성됐기 때문에 아티팩트를 그대로 물려받았다.

## 상태별 판정
| 상태 | 아티팩트 | 비고 |
|---|---|---|
| base | 정육면체 + 좌우 널빤지 + 분리된 작은 블록 | 원본(raw)부터 존재 |
| progress | 동일 (위치·크기만 다름) | base framed 를 입력으로 재생성된 결과 |

## 처방 — 재생성 없이 «실루엣 밖 제거»
고해상 원본을 열어 확인한 결과 **아티팩트는 머리·머리카락 실루엣 밖에만 있고, 그 아래 머리카락은
온전히 그려져 있었다**(정육면체 아래로 머리 정수리와 어두운 외곽선이 그대로 있다).
그래서 이미지 재생성 없이 실루엣 밖을 지우는 것으로 복구된다. (이 환경에는 이미지 생성 수단이 없다 —
`OPENAI_API_KEY`·`NVIDIA_API_KEY` 미설정, `cv2`·`numpy` 없음. PIL 만으로 처리했다.)

`repair_headgear.py`
1. 기준 좌표계(base 투명 원본 1122×1402)에서 머리카락 상단 절단선 `CUT` 을 1회 정의.
   값은 눈대중이 아니라 **열별 최소 휘도(= 머리카락 어두운 외곽선) 실측치**다. 좌측 널빤지가
   머리카락과 섞이는 x 278~310 구간만 확대 판독으로 보정했다.
2. 대상 3장은 상단 알파 프로필(행별 화소수+무게중심) 1D 매칭으로 `(s, tx, ty)` 자동 정합
   → 같은 곡선을 옮겨 쓴다. 손으로 3번 트레이스하지 않는다.
   (몸통 기준 정합은 재생성분에서 머리와 어긋난다 — progress 실측 8.5px. 그래서 상단 프로필을 썼다.)
   정합 후 «카키(정육면체 윗면) 잔여 최소화»를 목적함수로 국소 보정 1회.
3. 절단선 위쪽 제거 + 알파 1~16 의 «보이지 않는» 크로마 잔여 제거(★안 지우면 getbbox 가
   옛 아티팩트 크기를 잡아 프레이밍이 통째로 어긋난다) + 초록 스필 억제(머리 구간만) +
   고립 섬 제거(min 200px).
4. `transparent/` 에 보정 원본, `framed/` 에 128×154 미리보기.

`deploy_assets.py`
- 매니페스트 162 세 상태의 `source` 를 보정 원본으로 갱신하고,
  `ops/prod/betterhud/gen_npc_portrait_huds.py` 의 `frame()` 구도(알파 트림 → visible_box 맞춤 →
  가로 가운데·세로 아래)로 **배포 애셋을 다시 뽑는다**. 사본 복사·고정은 하지 않는다.
- 128×154 `asset` 은 RGBA, `_sm/_md/_lg/_xl` 은 P(256색) — 다른 157 NPC 와 같은 규격.
- `hd` 가 3 으로 유지되는지 검산한다(= `npc-dialogue-image.yml` 의 `scale: 0.3333` 불변).
  **HUD/layout/image yml 은 건드리지 않았다** → `betterhud-26-1-fix.sh` 재실행 불필요.
